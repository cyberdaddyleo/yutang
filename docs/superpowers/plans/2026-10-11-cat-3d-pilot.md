# Cat 3D Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver one real skinned 3D cat with reviewable gait and mat traversal in the existing app.

**Architecture:** Retain the current game simulation, saving and Canvas scene. Load a GLB into a theme-local Three.js renderer and composite the pilot cat at the existing actor render boundary. Preserve the old renderer as the default until visual approval.

**Tech Stack:** Blender 5.2.2 Python, glTF 2.0, Three.js, existing React/Vite/Electron.

**Spec:** ../specs/2026-10-11-cat-3d-pilot.md

## Global Constraints

- Only the cats theme receives a pilot renderer; other themes and saves remain unchanged.
- Source asset and redistribution/modification license must be recorded.
- Genuine weighted skinning, not flat image deformation or disconnected rigid primitive limbs.
- No publication or version changes; no bulk cat replacement before visual approval.
- User authorized proceeding with the proposed plan; no redundant permission checkpoints for local reversible work.

## Review Focus

- Invalid GLB, failed resource load: preserve working original render.
- Arbitrary heading: use continuous 3D yaw and confirm front/back limbs remain independent.
- Different display ratios: map root, feet, shadow and hit bounds with the original scene transform.
- Pause, hidden window or theme exit: no residual render loop and dispose GPU resources.
- Animations in Blender versus runtime: baked transforms must match, with no scale or axis drift.
